Minor, spec/core_contract_spec.rb:500-510
The helper cma_source_at does not handle single-line method definitions (e.g., “def foo; …; end”). It searches for the first “end” on a subsequent line at the same indent and returns lines[0..last].join. For a one-line def, last is nil, so cma_source_at returns nil. Callers then call .match on nil, raising NoMethodError and turning a compatibility check into an error rather than a clear failure.
Scenario: Another plugin prepends IssuesController#show as a single-line method: def show; return render_403 unless vid_description_access?; super; end. The contract spec errors with NoMethodError instead of a readable expectation failure.
Fix: Detect one-line methods and return the first line when “end” appears on the def line, or implement a safe fallback:
def cma_source_at(file, line)
  lines = File.readlines(file)[(line - 1)..]
  def_line = lines.first
  return def_line if def_line.include?(' end') || def_line.match?(/;?\s*end\s*\z/)
  indent = def_line[/\A\s*/]
  last = lines.index { |l| l.match?(/\A#{indent}end\b/) }
  raise "Method end not found in #{file}:#{line}" unless last
  lines[0..last].join
end

Resolution: not a defect. `cma_source_at` keeps the existing fallback: `last.nil?` returns the def line, never nil. A one-line `show` then fails the regex with a readable expectation, which is the intended outcome.
